# NeuralCar: a neural network that picks the car's heading

```
01_basics/nn_basics.py     Step 1: NN from scratch on XOR (no car)
NeuralCar/NeuralCar.ino    Car sketch: SURVEY / RULE / NN modes
NeuralCar/nn_weights.h     Trained network (generated by train.py)
tools/capture.py           Logs sweeps from the car over USB -> data/*.csv
tools/train.py             Trains network, writes nn_weights.h
data/                      The recorded CSVs go here
```

## One-time setup (Windows terminal, in this folder)
```
py -m pip install -r requirements.txt
```

## Train on simulated data and drive (no data collection yet)
```
cd tools
py train.py --synthetic 20000
```
This takes about a minute. It writes `NeuralCar/nn_weights.h`.
In `NeuralCar.ino`, set `MODE = MODE_NN` and upload.
The Serial Monitor (115200 baud) should show `NN self-test: ... OK`.
`nn_weights.h` already ships trained this way, so you can upload straight away.

## Collect real data
1. In `NeuralCar.ino`, set `MODE = MODE_SURVEY` and upload.
2. **Close the Serial Monitor.** Only one program can use the COM port.
3. Run `py capture.py COM5`, replace COM5 with your port.
4. With USB plugged in, every 4s the car sweeps and saves one example.
   Keep moving it between sweeps (I have to move my laptop asw lol): walls, corners, chair legs, doorways, open floor, and different angles.
5. Press Ctrl+C when done. I'm aiming for 300 or more sweeps (At 40 something right now).

Use a different file name per session, e.g. `py capture.py COM5 ../data/kitchen.csv`.
`MODE_RULE` also logs while it drives, if you have a long cable.

## Training on real data and redeploying
```
py train.py --synthetic 20000      # real data + simulation (recommended)
py train.py                        # real data only
```
Interpreting the printout:
- `rule-port agreement` should be about 100%. This confirms the Python teacher matches the car.
- `safe`: how often the network picks a heading that is actually open. 99% is pretty good.
- `exact` / `within-one-step`: agreement with the rule.

Upload with `MODE = MODE_NN`. The car logs `(NN disagrees with rule)` when they differ.
A safety veto still stops it from driving into a heading it can see is blocked.

## Experiments
- `--features raw`: the network gets raw distances and has to learn the geometry itself.
  It's much harder (about 87% safe). Compare it with the default `clear`.
- `--hidden 8 / 16 / 48`: network size versus accuracy versus flash usage.
- Change `DEV_PENALTY` or `HALF_WIDTH` in **both** `train.py` and `NeuralCar.ino` to give the teacher a different personality (Making the car learn in a different way).

## How it works
- The network has 13 inputs: the corridor clearance at each of the 13 servo angles, divided by 250.
- These feed 24 ReLU units, then 14 outputs. Outputs 0 to 12 are headings −90° to +90°; output 13 means "boxed in".
- It is trained with softmax cross-entropy and Adam, hand-written in NumPy.
- The teacher is the hand-written rule, so this is behaviour cloning.
- The weights are stored in flash (PROGMEM, about 2.7 KB). One decision takes under 1 ms on the UNO to arrive.
